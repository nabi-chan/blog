# 은솔 문체 가이드

`/write-post`, `/refine-post`, `/translate-post` 가 따르는 규칙이다. 은솔의 예전 글 12편(약 1만 자)을 분석해서 만들었다. 지금 형식으로 쓴 글은 3편뿐이라 "(추정)"이 붙은 규칙은 근거가 약하다. 은솔이 고쳐 주면 이 문서를 고친다.

예문은 모두 이 문서를 위해 새로 지은 것이다. about/cv 처럼 개인정보가 든 글의 원문은 예문으로 쓰지 않는다.

## 1. 어조

- 기술·정보를 전하는 문장은 **합니다체**로 쓴다.
- 독자에게 말을 걸거나 괄호로 덧붙일 때는 **해요체**로 한 단계 내린다.
  - 좋음: "캐시는 하루가 지나면 지웁니다. (설정에서 바꿀 수도 있어요)"
  - 나쁨: "캐시는 하루가 지나면 지운다. 설정에서 바꿀 수도 있다."
- 1인칭은 "저/제"다. 속마음은 따옴표 안에 반말 독백으로 쓴다.
  - 좋음: 빌드가 또 실패했습니다. '이번엔 또 뭐지...'
- 기술 글에도 소감이나 동기를 한 줄은 넣는다. 단, **은솔이 실제로 말한 것만** 쓴다. 지어내지 않는다.
- 유머는 짧은 반전, 말줄임, 가벼운 감탄사로 낸다. 기술 본문에는 이모티콘을 쓰지 않는다(추정).

## 2. 구조

- 기술 글은 인사 없이 `## X?` 정의 섹션으로 시작하고, 첫 문장은 "X는 ~입니다."로 쓴다.
  - 좋음: `## D1?` → "D1 은 Cloudflare 가 제공하는 SQLite 기반 데이터베이스입니다."
- 본문 소제목은 `##` 부터 쓴다. 제목(`#`)은 frontmatter 의 `title` 이 맡는다.
- 절차 소제목은 `~하기` 명사형으로 쓴다. 예: `## 마이그레이션 적용하기`
- 제품명은 원어 그대로 쓴다. 예: Cloudflare Workers, TanStack Start
- 문장은 대부분 60자 이내, 문단은 1~3문장이다. 강조할 한 문장은 따로 뗀다.
- 결론
  - 에세이형: `## 글을 마치며` → 요약 → 의견 → 독자에게 던지는 질문 → `### See Also...`
  - 튜토리얼: 마지막 단계에서 끝내도 된다.

## 3. 표기

- 용어
  - 제품명은 원어로 쓴다. 예: Turnstile, Paraglide
  - 일반 개념은 음차로 쓴다. 예: 캐시, 마이그레이션, 프리렌더
- 인라인 코드는 명령어와 API 이름에만 쓴다. 예: `pnpm build`, `crypto.subtle.deriveBits`
- 코드 블록
  - 언어 태그를 붙인다.
  - 블록 앞에 목적을 한 문장으로 쓴다.
  - 주석과 예시 값은 한국어로 쓴다. 영어판에서는 번역해도 된다.
- 리스트를 적극적으로 쓴다.
- UI 경로는 `[A] -> [B]` 로 쓴다. 예: `[Settings] -> [Domains]`

## 4. 맞춤법 (표준으로 교정한다)

교정하는 것:

| 틀림 | 맞음 |
|---|---|
| 이였다 | 이었다 |
| 할수 있다 | 할 수 있다 |
| 하는것 | 하는 것 |
| 하는김에 | 하는 김에 |
| 시작 해줍니다 | 시작해 줍니다 |
| oMLX 를 | oMLX를 (영문·코드 뒤 조사는 붙인다) |

- 명백한 오타도 고친다.

그대로 두는 것:

- 개발자 관용 외래어: 레포지토리, 어플리케이션 등
- 일부러 귀엽게 쓴 표기: 와자뵤, 연락처루 등

## 5. AI 문체 신호 걷어내기

글을 다 쓴 뒤 아래를 찾아서 고친다.

| 신호 | 예 | 고치는 방향 |
|---|---|---|
| 빈 수사 | "혁신적인", "강력한", "완벽한" | 수치나 사실로 바꾸거나 뺀다 |
| 과한 접속사 | 문장마다 "또한", "따라서", "이처럼" | 대부분 뺀다 |
| "~할 수 있습니다" 남발 | "확인할 수 있습니다", "사용할 수 있습니다" | "확인합니다", "씁니다" |
| 같은 문장 틀 반복 | "~는 ~입니다." 가 연달아 | 문장 길이와 시작을 바꾼다 |
| 번역투 | "~를 가지고 있다", "~에 대해서", "~하는 것이 가능하다" | "~가 있다", "~를", "~할 수 있다" |
| 없던 주장 | 근거 없는 "많은 개발자가" | 근거를 대거나 뺀다 |
| 장식용 마무리 | "앞으로가 기대됩니다" | 실제 다음 할 일이나 질문으로 |

## 6. 사람과 AI 가 믿기 쉬운 글

- 1차 경험을 쓴다: 실제로 해 본 것, 실제로 본 오류 메시지.
- 재현 조건을 적는다: 버전, 날짜, 환경.
- 1차 출처에 링크한다: 공식 문서, 저장소, 이슈.
- 첫 문단에 대상 독자와 얻을 것을 밝힌다.

## 7. 검색 (SEO)

- 제목: 검색할 말을 앞쪽에 둔다. 너무 길면 OG 카드에서 잘린다.
- 설명(`description`): 160자 이하이고, 글이 답하는 질문을 담는다.
- 소제목은 목차와 검색 결과에 그대로 보인다. 내용을 짐작할 수 있게 쓴다.
