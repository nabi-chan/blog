# /write-post

은솔의 초안으로 새 한국어 글을 쓴다. 초안: $ARGUMENTS

시작하기 전에 `AGENTS.md` 와 `docs/writing/style-guide.md` 를 읽는다. **커밋하지 않는다.**

## 1. 주제와 논지 잡기

- 초안을 읽고 다음을 편집 메모로 정리해 은솔에게 보여 준다. 메모는 원고에 넣지 않는다.
  - 이 글이 답하는 질문과 그 답(끝까지 읽은 독자가 가져갈 결론)
  - 결론 형식: 에세이형 / 튜토리얼 / 조사기 (문체 가이드 2절)
  - 다룰 것과 다루지 않을 것
  - 기준 독자 한 명(예: 이 주제를 처음 공부하던 때의 은솔)과, 그 사람이 아는 용어·모르는 용어
  - 독자가 얻을 것
- 모르는 용어는 본문에서 처음 필요한 자리에 풀어 쓰거나 `:term` 을 단다.
- 아래 중 하나에 걸리면 두 편으로 나눌지 은솔에게 묻는다. 나눈 글은 각각 혼자 읽혀야 한다.
  - 질문이 하나로 줄지 않는다.
  - 답에 닿기 전에 개념 하나를 설명하느라 절 하나가 통째로 든다.
  - 독자가 얻을 것을 한 문장으로 쓰지 못한다.
- 쓰다가 답이 바뀌면 메모도 고친다.
- 은솔의 경험·감정·동기는 초안에 있는 것만 쓴다. 없는 것은 지어내지 않고 물어본다.

## 2. 사실과 최신성 확인하기

- 버전, 가격, 지원 여부처럼 시간이 지나면 바뀌는 사실은 오늘 날짜 기준으로 웹에서 확인한다.
- 1차 출처(공식 문서, 저장소, 이슈)를 고른다. 확인한 출처는 본문 링크와 See Also 에 쓴다.
- 예전 작업을 쓰면 지금도 그 상태인지 확인한다. "고쳤다"고 쓰기 전에 지금도 고쳐져 있는지 본다.
- 성능·크기 수치는 직접 재거나 출처를 확인하고, 잰 도구·버전·날짜를 적어 둔다.

## 3. 글 쓰기

- 글 폴더: `content/posts/<slug>/index.ko.md`
  - slug 는 `YYMMDD` 또는 `YYMMDD-kebab-case` 다. `YYMMDD` 는 frontmatter `date`(KST)와 같아야 한다.
  - 하루에 한 편만 쓴다. 같은 날짜로 시작하는 폴더가 이미 있으면 은솔에게 날짜를 묻는다.
- frontmatter

  ```yaml
  ---
  title: "검색할 말이 앞에 오는 제목"
  description: "160자 이하. 이 글이 답하는 질문"
  date: "2026-10-20 12:00"      # KST
  tags: ["meta"]                # 태그 키 (소문자 ASCII)
  draft: true                   # 은솔이 확인하기 전까지
  ---
  ```

- 이미지는 글 폴더에 둔다. 상대 경로로 쓰고(`![대체 텍스트](./diagram.png "캡션")`), 대체 텍스트를 꼭 쓴다.
  - 한글·공백 파일 이름도 된다.
  - 폭을 줄이려면 `?w=400` 을 붙인다.
- 쓸 수 있는 문법과 쓰는 때는 문체 가이드 8절을 본다. 모르는 디렉티브는 빌드 오류다.
- 문체는 `docs/writing/style-guide.md` 를 따른다.

## 4. 체크리스트 점검하기

- **SEO**
  - 제목에 검색할 말이 앞쪽에 있다.
  - 설명은 160자 이하다.
  - 정의 다음 문단에 대상 독자와 얻을 것이 있다.
- **신뢰**
  - 1차 경험이 있다.
  - 재현 조건(버전·날짜·환경)이 있다.
  - 1차 출처 링크가 있다.
  - 지어낸 예시·로그·API 이름이 없다.
- **흐름**
  - 제목, 정의 다음 문단, 소제목만 읽어도 글이 무엇을 약속하고 어떤 순서로 가는지 보인다.
  - 문단 첫 문장만 이어 읽어도 주장이 쌓인다. 안 되면 접속사를 넣기 전에 문단 순서부터 바꾼다.
  - 처음 읽는 속도로 다시 읽으며 대상이 모호한 지시어와 빠진 전제를 찾는다.
  - 결론까지 쓴 뒤 정의 다음 문단(대상·얻을 것)을 결론에 맞춰 다시 쓴다.
- **AI 문체 신호**: 문체 가이드 5절 표대로 걷어낸다.
- **맞춤법**: 문체 가이드 4절대로 교정한다.

## 5. 태그·용어집 채우기

```sh
pnpm content:check --post <slug> --no-build
```

- 출력에서 "태그 표시 이름 없음", "용어집에 없는 :term" 항목을 찾는다.
  - 태그: `content/tags.yaml` 에 `{ key, ko, en }` 을 추가한다.
  - 용어: `content/glossary.yaml` 에 `{ key, ko: { name, definition }, en: { name, definition } }` 을 추가한다.
- **추가한 항목은 은솔에게 따로 보여 준다.**

## 6. 콘텐츠 검사 통과시키기

```sh
pnpm content:check --post <slug>
```

문제가 0개가 될 때까지 고친다. 경고(볼드 깨짐·맞춤법)도 고치되, 검사기가 잘못 짚은 것이면 그대로 둔다. 이 명령은 Content Collections 빌드(스키마·slug·하루 한 편)도 같이 본다.

## 7. 넘기기

- 바꾼 파일 목록과 은솔이 확인할 것을 보여 준다.
  - 사실 확인이 필요한 문장
  - 추가한 태그·용어
  - `draft` 상태
- 번역은 `/translate-post <slug>` 로 넘긴다.
